本节承接动作训练结果，说明将已确认的策略部署到 G1 实机的流程。部署必须按 **Dry Run → Live Run** 顺序进行：Dry Run 用于检查网络、DDS 通信、配置、观测与启动链路；只有在检查通过、周边安全且操作者已准备好急停后，才进入 Live Run。

> [!warning]
> Live Run 会向实机持续发送低层控制命令。执行前应确保机器人周围无人、悬挂或保护措施到位、遥控器急停可用，并确认没有遗留的控制进程或 MotionSwitcher 控制权。

## 4.1 March / GMR 部署产物与配置

`g1_robotref_160_taichi1.yaml` 是 Taichi1 实验的部署配置，不是 March 训练的输出，不能直接用于 March/GMR 部署。应以它为模板，新建 March/GMR 专用配置：

```text
/home/unitree/projects/whole_body_tracking/deployment/configs/g1_robotref_160_march_gmr.yaml
```

GMR 的 WBT 阶段输出为：

```text
# GMR 重定向后的 WBT 参考动作
/home/unitree/projects/whole_body_tracking/inputs/march_video/march_video_gmr_50fps.npz

# 训练运行目录与选定 checkpoint
/home/unitree/projects/whole_body_tracking/logs/rsl_rl/g1_flat/2026-09-09_04-16-52_baseline_march_video_gmr_100k/
model_30500.pt
```

部署脚本通常读取 YAML 中的 **Policy** 与 **Motion**：应将 `Motion` 改为 `march_video_gmr_50fps.npz`，将 `Policy` 改为由所选 checkpoint 导出的 `policy.onnx`，例如：

```text
/home/unitree/projects/whole_body_tracking/logs/rsl_rl/g1_flat/2026-09-09_04-16-52_baseline_march_video_gmr_100k/exported/policy.onnx
```

checkpoint 用于选择和导出策略，并不是命令行中 YAML 参数的替代品。

## 4.2 Dry Run

Dry Run 不应驱动机器人执行实机动作，用于验证部署链路是否正常。激活 Dry Run 环境后，在部署目录运行：

```bash
conda activate g1_live_dryrun

cd /home/unitree/projects/whole_body_tracking/deployment

PYTHONUNBUFFERED=1 python3 -u deploy_real_robotref_160.py \
  eno1 \
  g1_robotref_160_march_gmr.yaml \
  2>&1 | tee "/home/unitree/projects/whole_body_tracking/logs/real_single_dryrun_$(date +%Y%m%d_%H%M%S).log"
```


Dry Run 日志保存在：

```text
/home/unitree/projects/whole_body_tracking/logs/real_single_dryrun_<时间戳>.log
```

## 4.3 Live Run

仅在 Dry Run 通过后执行。Live Run 使用实机环境，并沿用相同的接口、脚本与配置文件；配置中必须确认已启用实机命令发送（`dry_run: false`）。


### 4.3.1 实机执行顺序

以下流程适用于 `g1_robotref_160_taichi1.yaml`。仅在 Dry Run 通过、现场安全条件满足且操作者已就位时执行。

1. 确认急停可用、保护到位、周边净空；使用遥控器 `L2 + X` 让 G1 稳定站立。

2. 在终端启动部署：

```bash
conda activate g1_live

cd /home/unitree/projects/whole_body_tracking/deployment

PYTHONUNBUFFERED=1 python3 -u deploy_real_robotref_160.py \
  eno1 \
  g1_robotref_160_march_gmr.yaml \
  2>&1 | tee "/home/unitree/projects/whole_body_tracking/logs/real_single_liverun_$(date +%Y%m%d_%H%M%S).log"
  
```

3. 看到以下提示后，按遥控器 **Start**：

   ```text
   Waiting for the start signal...
   ```

4. 机器人会在约 6 秒内插值到 `g1_robotref_160_taichi1.yaml` 的 `default_angles` 默认姿态。此时启动 OBSRun；若常驻的 systemd 服务已稳定发布 `/Odometry_2`，不得重复启动。

5. 等待终端确认：

   ```text
   OBSRun ready: /Odometry_2 rx ok; default pose hold complete.
   Waiting for the Button A signal...
   ```

6. 在保持默认姿态、等待 **A** 的期间，观察终端重复输出：

   ```text
   [PRE-A YAW ALIGN] ... yaw_err_odom= ... deg
   ```

   必要时谨慎调整机器人朝向，使 `yaw_err_odom` 接近 `0°`，最好保持在 `±5°` 内。

7. 再次确认站姿、朝向、定位与保护状态正常后，按遥控器 **A**。此后 policy 开始执行动作。

8. 全程盯守；出现异常时立即急停。正常退出时按 **Select** 或在终端按 `Ctrl+C`。

## 4.4 运行后记录

每次部署应记录：使用的模型/checkpoint、配置文件、执行日期、Dry Run 与 Live Run 日志路径、实机表现及异常处理结果。这样可以将实机结果追溯到对应的 WBT 训练运行。
